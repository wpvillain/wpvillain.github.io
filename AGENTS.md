## Post format

- Posts live in `_posts/YYYY-MM-DD-slug.markdown` (Jekyll, permalink `/:title/`). Front matter: `layout: post`, `title`, `description`, `date`, `categories`, `tags`.
- Raw HTML passes through kramdown fine, but **code blocks must be fenced with a language** (```` ```php ````, ```` ```nginx ````, ```` ```bash ````) — raw `<pre>` HTML gets no rouge highlighting. Never wrap a fence in a bare `<div>`/`</div>` line: kramdown treats the `<div>` as a raw HTML block and renders the fence literally.
- No local image paths; images would need to live under `assets/`. Dead external image tags should be removed, not kept.

## Moving a post from imagewize.com to wpvilla.in

Dev-only posts (Trellis/Nginx/Docker/WP-CLI/plugin internals) belong here, not on imagewize.com. Move procedure:

1. Export the WP post (`post_content`, title, date) from production.
2. Strip `<!-- wp:... -->` block comments; absolutize internal `href="/..."`/`src="/..."` to `https://imagewize.com/...`; convert every `<pre>` to a fenced block with a sniffed language; drop bare `<div>` wrappers around fences and dead `<img>` tags; **normalize unicode inside code blocks** (replace NBSPs with spaces, smart quotes with straight quotes, em/en dashes with `--`/`-`, ellipsis with `...`); build the front matter.
3. Commit + push — GitHub Pages builds automatically. Verify `https://wpvilla.in/<slug>/` returns 200 and code is highlighted **before** touching imagewize.com.
4. Add a 301 in `~/code/imagewize.com/trellis/nginx-includes/imagewize.com/seo-redirects.conf.j2` — **both** `location = /slug/ {` and `location = /slug {` variants (exact-match locations don't normalize slashes; the whole file uses pairs).
5. `cd ~/code/imagewize.com/trellis && trellis provision --tags wordpress-setup production`, verify the 301 live, then delete the original WP post on production.
